## 28. AI Operating Policy — scope, classification, injection defense, identity

**Insight Analyst is NOT a general-purpose AI assistant.** It is an *analytics investigation
assistant* with an intentionally restricted knowledge boundary.

### 28.1 Scope (may answer ONLY)
Uploaded dataset · current analysis · KPIs · charts · SQL · statistical tests · Root Cause Analysis ·
recommendations · executive reports · semantic model · data quality · governance · privacy ·
Investigation Graph · Decision Replay · InsightOS platform features / workflows / documentation /
configuration / architecture.

### 28.2 Out of scope (must politely refuse)
General programming, math, jokes, physics, resumes, poems, weather, history, translation, and any
general "ChatGPT-style" conversation. **Never** attempt partial answers; **never** use external
knowledge to answer unrelated questions.

### 28.3 Standard refusal (single, consistent)
> "I can only answer questions related to your uploaded data, the deterministic analysis generated by
> InsightOS, or how InsightOS works. I cannot assist with unrelated general-purpose questions."

### 28.4 Local intent classification (before any provider call)
```
User Question → Intent Classifier (LOCAL, rules + keyword/structure matching, NO LLM)
  → Supported?  No  → instant local refusal, NO API CALL
                Yes → AI Context Builder → Groq → Grounding Validation → Answer
```
Classes: `ANALYSIS · SQL · DATASET · ROOT_CAUSE · RECOMMENDATION · FORECAST · SEMANTIC_MODEL ·
INVESTIGATION · INSIGHTOS · UNSUPPORTED`. If `UNSUPPORTED`, the provider is **not** invoked and the
standard refusal is returned immediately. Classification is deterministic and uses **no** LLM call.

Benefits: saves API credits, lowers latency, prevents hallucinations, and blocks prompt injection
(malicious prompts never reach the model).

### 28.5 Prompt-injection protection
Requests attempting to subvert scope — e.g. "ignore previous instructions", "you are now ChatGPT",
"forget the dataset", "answer any question", "reveal your system prompt" — are detected locally and
classified `UNSUPPORTED` (or a dedicated `INJECTION` reason). They are refused **before** any model
call. The analyst remains restricted to InsightOS regardless of message content.

### 28.6 Grounding requirement
Every answer must be grounded in ≥1 of: uploaded dataset, semantic model, deterministic analytics,
Root Cause Analysis, SQL, statistics, forecast, recommendations, executive report, Investigation
Graph, or InsightOS documentation. If **no grounding source exists**, politely decline.

### 28.7 System identity
> "I am Insight Analyst, the explainable analytics assistant built into InsightOS. My role is to help
> investigate deterministic analytical results, explain business insights, and answer questions about
> your uploaded data and the InsightOS platform. I am intentionally not a general-purpose AI assistant."

### 28.8 Strict Investigation Mode (settings)
A settings toggle **"Strict Investigation Mode (Recommended)"**, **enabled by default**. When on,
only in-scope questions are answered; all unrelated requests are rejected **locally**. When off,
the classifier still runs but borderline classes are allowed through (dataset/analysis/InsightOS
scope always enforced; injection always blocked).

### 28.9 Facade enforcement
The classifier is the **first stage** of `AnalystFacade.ask` (§18), before context building or the
provider call. `UNSUPPORTED`/injection → immediate local refusal `InvestigationResponse`
(`grounding: 'Refused'`), no provider invocation, no cost.

## 29. Investigation Assistant — proactive, deterministic-first guidance

The analyst must **guide** investigation rather than wait for prompts. All suggestions are derived
from **deterministic analytics** (never invented) and become the **starting nodes** of the
Investigation Graph.

### 29.1 Observations (auto, on dataset load)
From the deterministic scorecard/RCA/quality artifacts, produce a short ranked list of findings, e.g.
"Revenue dropped 18%", "Retention improved", "Region East is unusual", "Marketing ROI doubled". Each
observation carries the deterministic `sourcePath` it came from — clicking one **starts an
Investigation Graph node** (no prompting).

### 29.2 Investigation Suggestions (instead of blank chat)
Contextual next questions: *Why did Revenue change? · Find hidden anomalies · Compare regions · Find
strongest drivers · Explain quality issues · Inspect recommendations · Show confidence.* Each maps to
a `ContextFocus` and seeds a node.

### 29.3 Investigation Templates (senior-analyst feel)
On dataset load, offer templates — **Revenue · Customer · Quality · Regional · Forecast** — each of
which **builds a multi-node Investigation Graph automatically** (seed + children) from the
deterministic analysis. Templates only include steps whose grounding exists in the current analysis.

### 29.4 Suggestion source (data types)
```ts
export type SuggestionKind = 'observation' | 'question' | 'template';
export interface Suggestion {
  id: string; kind: SuggestionKind; title: string;
  focus: ContextFocus; sourcePath?: string;   // deterministic provenance
  rationale?: string;                          // why it's suggested (from analytics)
}
export interface InvestigationTemplate {
  id: string; name: string; description: string;
  steps: Array<{ question: string; focus: ContextFocus }>; // built into the graph
}
```
Generators are **pure functions of deterministic artifacts** — no LLM call, no invented numbers.

### 29.5 UX visibility (deliberate, not hidden)
Per guidance: AI should disappear into the *workflow* but **Insight Analyst must be clearly exposed**
as "where the AI lives" (the project is judged partly on AI integration). Add an **"Explain This
Page"** affordance on Overview / Root Cause / Forecast etc., which opens the analyst focused on that
page's deterministic artifacts (in-scope by construction).

## 30. Stability — reaffirmed
Everything in §28–§29 is additive and flag-gated. The classifier and suggestion generators are pure,
deterministic, browser-only, and run with AI disabled (they simply gate/seed; no provider needed to
produce suggestions). No engine module or deployment is modified; zero regression.
